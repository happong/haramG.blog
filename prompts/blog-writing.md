# 블로그 글 작성 프롬프트 (요구사항 체크리스트)

> Claude가 대시보드의 글을 다듬을 때 **매번 이 파일을 처음부터 읽고** 아래 순서를 지킨다.
> 요구사항이 바뀌면 이 파일을 먼저 고친다. 출처: 하해님과의 대화에서 확정된 내용.

## 작업 순서

```
1. 프롬프트 확인  →  2. 콘텐츠 글 확인  →  3. 콘텐츠 글 작성
```

### 1. 프롬프트 확인
- [ ] 이 파일 전체를 읽었다
- [ ] `guides/style-guide.md` (말투) 를 읽었다
- [ ] `guides/platform-formats.md` (네이버 / 티스토리 차이) 를 읽었다

### 2. 콘텐츠 글 확인
- [ ] 대시보드 DB `posts` 컬렉션을 읽었다 (`ArtifactData` list)
- [ ] 작업 대상: `stage == "memo"` 이고 `naverDone != true` 인 글
- [ ] 각 글의 메모·카테고리·경험한 날·사진(`photos` 순서 = 사진 번호)을 확인했다
- [ ] 사진은 `Artifact` read(`path` = asset id)로 직접 열어 보고 내용을 확인했다
- [ ] **글을 쓰기에 사실이 부족하면 쓰지 않는다** → `questions`에 질문을 적고 `stage: "question"` 으로 바꾼다
  - 예: 가격, 위치/찾아가는 길, 운영시간, 메뉴 이름, 좋았던 점/아쉬웠던 점, 재방문 의사, 개발 글이면 공부하다 헷갈렸던 점

### 3. 콘텐츠 글 작성
- [ ] 네이버 초안 → `draftNaver`
- [ ] 개발 글(`dev`)이면 티스토리 초안 → `draftTistory` (네이버와 **다른 각도로 처음부터 새로** 작성)
- [ ] 작성 후 `stage: "draft"` 로 바꾸고 `questions` 는 비운다 (남은 확인 사항이 있으면 초안 맨 위 `[확인 필요]` 로 표시)
- [ ] 아래 **작성 규칙**을 하나씩 대조했다
- [ ] 대시보드 DB를 저장소 `content/` 로 동기화하고 커밋·푸시했다 (`scripts/sync_dashboard.py`)

## 작성 규칙

### 사실과 정확성 (가장 중요)
- 메모·사진에 없는 맛, 서비스, 분위기, 가격, 결과는 **절대 지어내지 않는다**
- 가게 주소·운영시간·가격은 메모에 있는 것만 쓴다. 바뀔 수 있으니 발행 전 확인하라고 `[확인 필요]` 로 표시
- 리서치로 넣은 정보는 모두 출처 URL 을 붙인다. 확인 못 한 것은 "확인하지 못했다"고 쓴다
- 사람·장소 호칭은 메모 표현 그대로 쓴다 (임의로 통일하거나 바꾸지 않음)
- 개발 용어는 정확하게: 예) for문 첫 줄을 "조건"이라고 부르지 않는다
- 개발 글의 코드는 **실제로 실행해 보고** `#결과` 를 적는다

### 말투 (`guides/style-guide.md` 요약)
- "안녕하세요, 하해입니다! ☺️" 로 시작, 계절·날씨나 계기로 도입
- 해요체 기본 + 합니다체 섞임, "~더라고요"(구요 X), 진짜/너무/정말/딱
- 독자에게 질문·권유, 실용 팁, 구체적 숫자
- 글 분위기에 맞춰 이모지 양 조절 (부정 후기는 최소)
- 한 줄에 한두 문장, 빈 줄 넉넉히
- 해시태그 20~30개
- 해시태그 뒤에 독자와 소통하는 한 줄 (특히 개발 글·퀴즈 글)

### 사진
- 초안 본문에 `[사진 1]`, `[사진 2]` … 로 넣을 위치 표시 (번호 = 대시보드 사진 순서)
- Claude 는 실사 사진을 만들지 않는다. 개발 글의 도표는 필요할 때만 제안

### 카테고리별
| 카테고리 | 주간 목표 | 플랫폼 | 규칙 |
|---|---|---|---|
| 맛집·추천 `food` | 주 2회 | 네이버 | 위치(찾아가는 길) → 운영시간 → 분위기/항목별 후기 → 가격 → 추천 대상·재방문 → 마무리 |
| 개발 공부 `dev` | 주 1회 | 네이버 + 티스토리 | 파이썬 기초 시리즈. 지난 글 연결 → 정의 → 게임 PM 업무 비유 → 코드+#결과 → 중요한 점 → 자주 하는 실수 → 실무 예시 → 퀴즈 → 다음 편 예고 |
| AI 활용기 `ai` | 주 1회 | 네이버 | 유입용. 뉴스 요약 X, **직접 써본 경험**(1~2줄이라도) 중심 + 출처 |

### 네이버 vs 티스토리 (개발 글)
- 네이버: 공부 후기형 (과정·헷갈린 점·느낀 점), 제목 예 "OO 공부하다 막혔던 후기"
- 티스토리: 정리·레퍼런스형 (문제 → 원인 → 해결 코드 → 요약 표), 검색 질문형 제목
- **코드 예시만 바꾸고 문장을 재사용하지 않는다** — 문장도 처음부터 새로 작성

### 일정·우선순위
- 한 주에 경험이 많으면 다음 주·다다음 주로 나눠 `planned` 제안 (주간 목표 기준)
- 시즌 글(`season: true`)은 `seasonEnd` 가 가까운 순서로 우선 배치

## 운영 요구사항 (대화에서 확정된 것)
1. 글은 하해님이 실제로 경험한 것만 쓴다
2. 올린 글 / 안 올린 글을 구분한다 → 대시보드 체크박스 (네이버 발행, 티스토리 발행)
3. 시즌 글은 우선순위를 높이고 알린다 → 대시보드 "챙길 것" + GitHub 이슈 알림
4. 말투를 맞춰 쓰고 사진 위치까지 표시한다. 발행(업로드)은 하해님이 직접 한다 (네이버·티스토리 글쓰기 API 종료로 알려짐)
5. 주 2회 맛집·추천, 주 1회 개발, 주 1회 AI 활용기
6. 메인은 네이버, 티스토리에는 개발 글만
7. 블로그 URL 은 기록하지 않아도 된다 (Claude 가 네이버 페이지에 접속할 수 없음)

## DB 필드 (대시보드 `posts` 컬렉션)
| 필드 | 누가 | 의미 |
|---|---|---|
| title, category, visited, planned, priority, season, seasonEnd, memo, photos | 하해 | 기본 정보·경험 메모·사진(asset id 배열) |
| stage | 둘 다 | `idea` 메모 전 / `memo` 다듬기 요청 / `question` Claude 질문 / `draft` 초안 완료 |
| questions | Claude | 글 쓰기 전에 확인할 질문 |
| draftNaver, draftTistory | Claude | 초안 |
| naverDone, naverDoneAt, tistoryDone, tistoryDoneAt | 하해 | 실제 발행 체크 (날짜는 체크할 때 자동 기록) |
