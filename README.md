# haramG.blog
블로그 히스토리 작성 — 직접 경험한 콘텐츠를 쌓아두고, 나눠서 발행하고, 놓치지 않게 관리하는 저장소입니다.

## 운영 방침

| 플랫폼 | 올리는 글 | 비고 |
|---|---|---|
| 네이버 블로그 | 맛집·추천 / 개발 공부 / AI 활용기 | 메인 |
| 티스토리 | 개발 공부만 | 계정 개설 예정 |

### 주간 목표

| 카테고리 | 횟수 | 내용 |
|---|---|---|
| 맛집·추천 (`food`) | 주 2회 | 직접 방문한 곳 기반 |
| 개발 공부 (`dev`) | 주 1회 | 기초 개념 글 (예: "for문이란?") |
| AI 활용기 (`ai`) | 주 1회 | 유입용. 직접 써본 AI 도구 후기 |

### 글쓰기 원칙

- **경험 기반**: 글의 사실 근거는 직접 작성한 "경험 메모"입니다. 경험하지 않은 맛·서비스·결과는 쓰지 않습니다.
- **출처 필수**: 리서치로 넣은 정보는 모두 출처 URL을 붙입니다.
- **말투 통일**: `guides/style-guide.md` 기준. 기존 네이버 글 3~5개를 바탕으로 채울 예정입니다(현재 비어 있음).
- **같은 경험, 다른 각도**: 개발 글을 네이버와 티스토리에 모두 올릴 때 **코드 예시만 바꾸면 안 됩니다.** 설명 문장이 같으면 유사문서로 판단될 수 있습니다. 네이버는 후기형, 티스토리는 정리·레퍼런스형으로 각각 처음부터 새로 씁니다. → `guides/platform-formats.md`
- **AI 활용기**: 뉴스 요약형 글보다, 본인이 직접 써본 경험을 1~2줄이라도 넣은 글로 씁니다.

## 역할 분담

| Claude가 하는 것 | 직접 하는 것 |
|---|---|
| 경험 메모 → 플랫폼별 초안 작성 | 경험 메모 작성 (짧아도 됨) |
| 말투 가이드 정리, 리서치(출처 포함) | 사진 촬영·첨부 파일 준비 |
| 발행 일정·백로그 관리, 이슈 알림 | 초안 검토 후 **블로그에 붙여넣고 발행** |
| 개발 글용 도표·다이어그램 | 발행 후 `status`, `published`, URL 기록 |

### 자동 업로드가 안 되는 이유

- 네이버 블로그와 티스토리는 글쓰기 API가 종료된 것으로 알려져 있습니다(커뮤니티 자료 기준, 공식 공지는 확인하지 못함). 그래서 **마지막 발행은 직접** 합니다.
- Claude는 실사 사진을 새로 만들 수 없습니다. 맛집 사진은 직접 찍은 사진을 사용합니다.

## 구조

```
content/
  food/   맛집·추천
  dev/    개발 공부
  ai/     AI 활용기
templates/  카테고리별 글 템플릿 (frontmatter 포함)
guides/
  style-guide.md      말투 가이드
  platform-formats.md 네이버 / 티스토리 포맷 차이와 발행 규칙
images/     글에 들어갈 사진
scripts/backlog.py  현황 리포트 · 시즌 알림 계산
.github/workflows/blog-alerts.yml  GitHub 이슈 알림
```

## 사용 흐름

1. 경험하면 `templates/<카테고리>.md`를 복사해 `content/<카테고리>/날짜-이름.md`로 저장하고 **경험 메모**만 채웁니다.
2. Claude에게 초안 작성을 요청 → `status: draft` → 검토 후 `ready`.
3. 발행 날짜를 정하면 `planned`에 입력합니다. 한 주에 경험이 많으면 다음 주, 다다음 주로 나눠 날짜를 넣습니다.
4. 올린 뒤 `status: published`, `published`, `naver_url`(티스토리면 `tistory_url`)을 채웁니다.

시즌 콘텐츠는 `season: true`, `season_end: YYYY-MM-DD`를 넣으면 우선순위가 올라가고 알림 대상이 됩니다.

### 상태값

| status | 의미 |
|---|---|
| idea | 경험만 하고 메모 전 |
| draft | 초안 작성됨 |
| ready | 검토 끝, 발행 대기 |
| published | 발행 완료 (네이버 기준) |

## GitHub 이슈 알림

| 언제 | 무엇을 |
|---|---|
| 매일 08:47 KST | `season_end`까지 14일 이하로 남은 미발행 시즌 글마다 `[시즌 알림]` 이슈 생성. D-7·3·1·0 및 마감 이후에는 댓글 추가, 발행하면 다음 날 자동으로 닫힘 |
| 매주 월요일 08:41 KST | 주간 목표 대비 현황, 이번 주 예정 글, 예정일 지난 글, 일정 미정 후보를 `weekly-report` 이슈로 생성 |

- 예약 실행은 **main 브랜치에 있는 워크플로만** 동작합니다.
- Actions 탭 → Blog alerts → Run workflow 로 즉시 실행할 수 있습니다.
- 알림을 받으려면 저장소 Watch 설정에서 Issues 알림을 켜두세요.
- 주간 리포트는 현재 네이버 발행(`status`) 기준입니다. 티스토리 발행 여부는 `tistory_url`로만 기록됩니다.

### 로컬에서 확인

```bash
python3 scripts/backlog.py status            # 이번 주 현황
python3 scripts/backlog.py alerts --days 14  # 시즌 알림 대상
```

수익 규모는 확인된 자료가 없습니다. 신청 전에 각 플랫폼 공식 고객센터에서 최신 기준을 확인합니다.
